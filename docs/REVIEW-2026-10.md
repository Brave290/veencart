# Site review — October 2026

Scope: public site (`/`, `/services`, `/services/*`, `/track`, 404, error pages),
header/footer layout, responsiveness, speed, and tests. Measured against the
production build at 320, 390, 768, 1024 and 1440 px widths, in light and dark
theme, with Playwright on Chromium.

## Errors found and fixed

| # | Area | Problem | Fix |
|---|------|---------|-----|
| 1 | Navigation | Header and footer linked to `/book`, `/store`, `/contact`. None existed, so each returned 404. | Added honest status pages for all three (no invented prices, dates or contact details). A test checks every internal link returns 200. |
| 2 | Header layout | On desktop the logo was centred and the nav sat on the right. | Logo and nav text now sit on the left; theme toggle, Book CTA and menu button sit on the right, at every width. |
| 3 | Touch targets | Header controls were 40 px, the logo link was 19 px tall, footer links were about 21 px tall. | Controls are 44 px minimum on all breakpoints. Footer links are 44 px tall rows. |
| 4 | Speed | A full-screen preloader held the home page for at least 1,050 ms on every visit (fallback 3.2 s). | Removed. Content paints immediately. |
| 5 | Speed | The header logo was a 743 KB PNG, loaded on every page. | Added 256 px and 512 px pre-sized copies (56 KB and about 180 KB). The header and footer use the 256 px file; the hero uses the 512 px file. Brand assets cached for 7 days. AVIF/WebP image formats enabled. |
| 6 | Speed | Icon library imported in full. | `optimizePackageImports` for `lucide-react`; `compress` on; `X-Powered-By` removed. |
| 7 | Content | Stagger reveal silently dropped every child after the sixth. | All children render. Only the animation delay is capped. |
| 8 | SEO / robots | Two conflicting `robots` meta tags on the 404 page (`noindex` from the framework plus `noindex, follow` from our metadata); root layout also declared `index`. | Removed the redundant metadata. A single `noindex` tag is emitted. Found by the new Playwright suite. |
| 9 | Accessibility | 404 and error pages nested a `<button>` inside a `<Link>` (invalid HTML, double focus). | Use link-styled buttons instead. Test asserts zero nested interactive elements. |
| 10 | Dark mode | Active nav item was teal text on a dark teal pill (low contrast). | Active item is a solid primary fill with white text in both themes. |
| 11 | Honesty | Home page said "Guest booking available" but booking is not built. | Replaced with "Tracking by reference". |
| 12 | Error page | Plain layout, no site header, inconsistent with the rest of the site. | Redesigned to match the site. Error details still never shown to the visitor (only the digest). |

## New features and pages

- **404 page redesigned.** Large "404" display, plain statement that the page does not exist, two real actions, and a verified list of destinations. Still no fake search or guessed suggestions.
- **Maintenance page** at `/maintenance`. States planned maintenance without inventing a return time. Marked `noindex`.
- **Mobile menu** is now a proper dialog: `inert` when closed, Escape closes it, body scroll locks, active page is marked with `aria-current`.
- **Status pages** for `/book`, `/store` and `/contact`, built on one shared component.

## Verification

- `npm run typecheck`, `npm run lint`, `npm run check:contrast`, `npm test` (86 tests), `npm run build`: all pass.
- `tests/e2e/layout.spec.ts` (new, 20 tests) plus the existing `public-site.spec.ts` (12 tests): 32 of 32 pass on Chromium.
- Audit across 5 widths and 9 routes: zero horizontal overflow, zero broken internal links, zero console errors on any page.

## Still open (not done in this change)

- **Typeface.** The design brief specifies Inter. It is not loaded; the site uses the system sans-serif stack, which is the fastest option. Adding Inter via `next/font` would need network access at build time.
- **Maintenance HTTP status.** `/maintenance` returns 200. A true maintenance window should return 503 with `Retry-After`; that needs a hosting-level rule or a runtime route handler.
- **Unused video.** `public/brand/veencart-logo-motion.mp4` (about 350 KB) is not referenced anywhere. Left in place; it does not load on any page.
- **Contact details.** `/contact` publishes no phone, email or hours because the business has not confirmed them (see the layout comment in `app/layout.tsx`).
- **Booking and marketplace.** Not built. `/book` and `/store` say so honestly.
- **Real-device testing.** Tests ran in headless Chromium at emulated sizes. Safari/iOS and low-end Android should be checked by hand before launch.
